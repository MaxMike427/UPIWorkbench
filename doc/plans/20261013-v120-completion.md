# v1.2.0 完成设计

## 目标
依据 `doc/1.2.0.md`，让服务商选择真正参与任务配置，提炼与支付拥有独立选择，支持本地提炼和代理，账号库提供服务商购买入口，并保留现有任务快照、自动推送和日志行为。

## 方案
1. **服务商目录**：沿用 `app/services/provider_catalog.py` 作为唯一公开服务商目录；API 返回能力字段和公开购买入口，不返回凭证。
2. **配置**：保留 `upi_provider.*` 兼容旧版本；新增 `extract_provider.*` 和 `payment_provider.*`，新任务快照保存两个选择。综合服务商可以同时作为提炼和支付服务商。
3. **执行**：现有 ytc/Nerver 作为综合提炼+支付适配器；本地 `upi-zero-link` 作为提炼适配器，并通过 Masi `/api/scan-orders` + `/api/orders/{id}` 完成独立支付。未实现直接适配器的供应商返回明确错误而不误报成功。
4. **代理**：本地提炼和远程 ytc 都使用任务创建时的按账号代理；ytc 保持 HTTP/HTTPS/SOCKS5 限制，本地允许 HTTP/HTTPS/SOCKS5/SOCKS5H/SK5（SK5 在解析层规范化）。
5. **自动推送**：创建任务增加 `auto_push` 开关，默认沿用集成开启时自动推送；关闭时成功接码不入队，成功库手动推送仍可用。

## 验收
- `/api/configs/workspace` 返回三个服务商选择和三类 CDK 配置，旧配置仍可读写。
- `/api/providers?capability=extract|pay|sms` 返回对应能力的目录条目，综合服务商出现在提炼和支付列表。
- 新任务 `snapshot_json` 含 `extract_provider`、`payment_provider`、`auto_push`；重试沿用快照。
- 本地提炼能接收账号 AT、账号邮箱和任务代理；缺依赖或执行失败返回可读错误。
- 设置和账号库 UI 存在独立下拉、购买链接和 CDK 更新，去掉兼容综合选择重复项。
- 现有全套测试、UI 工作流和浏览器验收保持通过。
