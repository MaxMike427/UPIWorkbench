# UPI Workbench V1.1.0 更新需求与验收说明

> 文档日期：2026-10-12
> 基线版本：V1.0.0
> 来源：[1.1.0更新内容.md](./1.1.0更新内容.md)
> 状态：V1.1.0 功能已在本地源码实现并通过自动化/隔离浏览器验收；真实 ytc、handy 和目标 sub2api 实例仍需上线前联调，不代表已创建发布标签。

## 1. 版本目标与边界

V1.1.0 在现有账号任务工作台上完成以下四类更新：

1. 修复“选择少量账号创建任务，却带入全部账号”的问题，明确选择、取消勾选和任务候选列表的对应关系。
2. 新增“代理库”，管理外部代理并为 ytc 提链支付提供代理，不依赖平台已关闭的内置代理。
3. 新增“集成”，配置推送模板并将成功账号推送到用户的 sub2api 实例；实例 URL、管理员 Admin Key 和开关在设置中保存。
4. 在接码 CDK 旁增加接码开关，允许支付成功后不接码，并显示“已成功未接码”。

保留现有能力：资格检查、提链最多 5 次尝试、接码无限间隔重试、任务暂停/继续、失败新建重试任务、终端进度、账号状态同步、TXT/JSON 下载、任务 MD 记录、并发控制与账号库分页。

本次需求取代 `20261012.md` 中“工作区仅五项”的限制：工作区增加代理库和集成，共七项。不额外增加独立接码页、独立提链页、独立日志页或其他模块。

## 3. 修复账号选择与创建任务

### 3.1 选择必须与候选任务账号一一对应

- 在账号库勾选 N 个账号，点击“用选中账号创建任务”，候选列表和确认页只能显示这 N 个账号。
- 该入口不能默认全选账号库，也不能将当前页的全部账号或全部分页查询结果写入任务。
- 在任务管理点击“创建任务”时，从明确的选择步骤开始；不得无提示继承上一个已完成或已取消向导的历史选择。
- 同一轮选择中翻页、搜索或每页数量切换，应保留用户已选账号；“全选”只作用于当前页，不能隐式全选所有页。
- 取消勾选后，该账号立即从本次候选列表和计数中移除。
- 确认页应允许移除单个候选账号，或返回上一步取消勾选；返回后数量与列表必须一致。
- 无选中账号时，“下一步”和“开始任务”不可执行。

### 3.2 提交与后端校验

- 创建请求的 `credential_ids` 必须来自当前确认列表，不能重新用全库查询覆盖用户选择。
- 后端对 IDs 去重、检查存在性，并以实际成员数量写入 `total_credentials`。
- 任务详情中的邮箱和成员数量必须与请求内容一致。
- 创建请求处理中禁用重复提交；创建成功但启动失败时，再次启动复用已创建任务，不产生重复任务。
- 用户修改候选账号后，不能继续使用成员已不匹配的旧任务编号。取消或修改已创建但未启动任务的处理方式需要明确提示，不能静默修改已运行任务。

**“自动踢出任务列表”的边界（已确认）：**仅作用于尚未提交执行的候选账号列表。任务已开始后，不因用户在账号库取消勾选而移除历史成员或撤销支付。

### 3.3 必须覆盖的回归场景

| 场景 | 预期结果 |
|---|---|
| 100 个账号中只选 2 个 | 候选列表 2 个，创建请求 2 个，任务成员 2 个 |
| 当前页全选 20 个，再取消 3 个 | 候选列表和创建请求均为 17 个 |
| 第 1 页选 1 个，第 2 页选 2 个 | 本轮任务含 3 个，而不是任一页全部账号 |
| 搜索、切换每页数量后取消其中 1 个 | 仅移除被取消账号，其他已选账号保留 |
| 关闭向导，再从任务管理创建新任务 | 不静默带入旧选择 |
| 创建成功、启动因配置错误失败 | 修正配置后复用原任务，不重复创建 |

## 4. 新增代理库

### 4.1 页面布局与交互

- 页面位于“账号库”与“任务管理”之间。
- 顶部设置“启用代理库”开关，可关闭并保存。
- 提供多行输入框，每行一个代理地址；空行可忽略。
- 支持保存，并显示有效数量及无效行号；错误提示不得显示代理用户名或密码。
- 保存后的列表显示协议、主机、端口、启用状态；代理密码脱敏。
- 关闭开关不删除已有代理，重新打开后可以继续使用。
- 开关变化只影响之后创建的任务，已经提交到 ytc 的订单继续沿用原任务代理快照，不能重新建单替换。

### 4.2 协议支持与校验

本地输入支持常见格式：`http://`、`https://`、`socks5://`；用户所说的 `sk5` 在界面说明中对应 SOCKS5。`socks5h://` 的远端解析行为和 ytc 是否接受，需要联调确认。

脱敏示例：

```text
http://proxy.example.com:8080
https://proxy.example.com:8443
socks5://user:REDACTED@proxy.example.com:1080
```

校验要求：

- 必须含受支持协议、有效主机及 1–65535 范围内的端口。
- 禁止换行注入、未知协议、无端口地址及格式不完整的认证信息。
- 用户名/密码中的特殊字符按 URL 编码处理，不直接拼接进日志或命令。
- 是否接受无协议的 `host:port:user:pass` 或 `sk5://` 简写，标为待确认；不能将其默认为标准 URI。

### 4.3 ytc 对接与关闭语义

现有 ytc 前端包中可见建单字段 `proxy_source` 和 `proxies`，Workbench 已按下列方式传入：

- 启用代理库：通过 `proxy_source="provided"` 与代理文本 `proxies` 提交选中代理。
- 不能仍提交内置代理模式并宣称代理库生效。
- 本地支持某协议不代表 ytc 一定支持该协议，需逐项联调 HTTP/HTTPS/SOCKS5。
- 开关启用但无有效代理时，任务开始前报错，不进入支付。
- 代理连接失败时在终端显示“代理连接异常”，不能将代理问题判成账号无资格，也不能泄漏认证信息。

**已确认：**代理库关闭或有效代理为空时，阻止新提链并提示配置；不传内置代理模式、不回退直连。已提交订单仍查询原订单，已支付账号可以继续接码。

代理分配建议：任务创建时固化有效代理集合，账号按稳定顺序分配；同一已提交订单保持原代理，不在网络超时后盲目换代理重新支付。具体轮换策略待联调确认。

## 5. 新增 sub2api 集成

### 5.1 设置与集成页面的分工

**设置页新增 sub2api 连接项：**

- sub2api 实例 URL。
- 管理员 Admin Key，密码型输入、脱敏显示、允许新值覆盖。
- 启用/关闭集成推送开关。
- 保存按钮及连接校验反馈。

**“集成”页面提供：**

- 实例连接状态（不回显 Admin Key）。
- 推送模板：分组、账号并发、计费倍率、可用模型设置。
- 成功账号推送结果：待推送、推送中、已推送、失败、跳过、需核对。
- 失败重试、远端账号 ID 与已应用模板摘要。

关闭推送不清空 URL、密钥或模板，也不影响本地任务完成、成功库与文件导出。连接测试不得通过创建真实账号、支付或修改远端分组来判定连通。

### 5.2 sub2api API 文档依据与限制

参考：[sub2api API 参考](https://opendeep.wiki/Wei-Shaw/sub2api/api-reference)。实际开发须再核对目标实例的版本与 OpenAPI/源码。

| 公开文档信息 | 可用于本项目的内容 | 尚需确认 |
|---|---|---|
| 官方源码 `x-api-key: <admin-api-key>`；JWT 仍受支持 | 本实现使用 Admin Key 请求头，并保留目标实例联调要求 | 目标实例是否启用该中间件、权限和路径版本 |
| `GET /api/v1/admin/groups` | 获取可选择的远端分组 | 目标实例字段、分页和权限 |
| `POST /api/v1/admin/accounts/import/codex-session` | 导入 AT/Refresh Token 或包含 token 字段的 JSON，返回逐条结果 | handy 导出的 sub2api JSON 能否直接作为 `content`，还是需提取内部账号凭据 |
| `POST /api/v1/admin/accounts` | 直接创建指定平台和类型的账号 | 与导入接口的选择、重复检测及凭据要求 |
| 统一响应 `code/message/data` | 同时检查 HTTP 状态与业务 `code`，逐项读取导入结果 | 部分实例是否存在直接返回数据的兼容格式 |

优先评估 `import/codex-session` 的正式契约，不通过网页模拟管理员操作，不猜测导入端点，不将整个 ZIP 二进制直接当 JSON 请求体。

### 5.3 推送模板字段映射

| 用户配置 | 公开文档中已列出的字段或机制 | 校验与边界 |
|---|---|---|
| 分组 | `group_ids` | 选择实际存在且适用于 OpenAI 的分组；不要静默绑定默认分组 |
| 并发 | `concurrency` | 正整数；这是远端账号并发，与 Workbench 任务执行并发分开 |
| 计费 | `rate_multiplier` | 文档支持倍率；若“计费”指逐模型单价或其他计费方式，另行确认，不能误当倍率 |
| 可用模型 | 本实现使用官方导入请求的 `credential_extras.model_mapping` 作为账号级映射 | 目标实例是否允许该账号级字段及其实际模型能力，需联调；不修改共享分组白名单 |
| 不分组 | `skip_default_group_bind` | 空分组场景评估 `true`，必须确认不会自动挂默认分组 |
| 已存在账号 | `update_existing` | 更新还是跳过需明确；不可无提示覆盖远端已配置账号 |

“可用模型”先作为模板要求记录并校验。具体落在既有分组选择、分组白名单设置还是目标版本的账号能力字段，列为待确认，未联调前不能发送猜造的 `models` 字段。

### 5.4 推送触发与可靠性

- 开关启用且连接、模板校验通过后，成功账号加入持久化推送队列。
- 推送使用接码后保存的真实 JSON/OAuth 凭据，不能以旧 AT 冒充已获取 Refresh Token 的账号。
- 保存本地账号/凭据指纹、实例标识、模板快照和远端账号 ID，避免重复轮询或进程重启重复导入。
- 同一账号对同一实例已成功推送后，默认不重复创建；显式更新行为需确认。
- 批量响应分别记录 `created/updated/skipped/failed`，不能只根据 HTTP 200 将全部账号记为推送成功。
- 401/403 提示管理员密钥或权限异常；429 遵守 `Retry-After`；临时网络错误允许间隔重试。
- 请求超时且远端可能已写入时标为“需核对”，先查远端结果，不盲目再次创建。
- 推送失败只影响集成状态，不回退支付、接码或本地成功结果，不再次消耗平台额度。

URL 校验须限定 HTTP/HTTPS，规范化基础 URL，避免重复拼接 `/api/v1`；Admin Key 仅由后端使用，不发送到前端日志、导出文件或第三方平台。

## 6. 增加接码开关

### 6.1 设置与任务快照

- 在接码 CDK 旁显示“启用接码”开关，支持保存。
- 默认开启，保留 V1.0.0 原流程。
- 创建任务时记录该开关；任务详情展示“接码开启”或“接码关闭”。
- 修改全局开关不改变已经支付或已经开始接码的任务，不让任务中途静默跳步。
- 关闭接码后，不要求填写接码 CDK，也不调用 handy 自动登录、取号、轮询或导出接口。

### 6.2 两种流程

**开启接码：**

```text
TXT 原 AT → 资格检查 → ytc 提链支付成功
          → 接码绑定 → CPA/sub2api JSON 保存
          → 全流程成功 → 可选 sub2api 推送
```

**关闭接码：**

```text
TXT 原 AT → 资格检查 → ytc 提链支付成功
          → 已成功未接码 → 任务 MD 记录
```

资格不通过、资格查询异常和未确认支付的账号不能进入任一成功分支。已生成链接仍不等于支付成功，继续使用原支付订单确认逻辑。

### 6.3 状态、成功库与推送限制

- 账号库必须明确显示 **“已成功未接码”**，建议内部值为 `paid_without_sms`，不能复用 `done` 而造成混淆。
- 任务详情与 MD 报告单独统计“全流程成功”“已成功未接码”“失败”，不将未接码数混入已接码成功数。
- 未调用 handy 时不会有其生成的 CPA/sub2api JSON；下载按钮应说明“尚未接码，暂无对应产物”，不能生成伪造 JSON。
- 历史已下载文件是否仍可导出，要以对应接码记录为依据，不能将旧文件标作本次新产物。
- **已确认：**关闭接码但支付成功的账号进入成功库和仪表盘成功总数，并单独显示“已成功未接码”；仅允许 TXT，不生成 CPA/sub2api JSON。
- **已确认：**“已成功未接码”账号不自动推送 sub2api；集成页面的手动批量选择也逐条拒绝该状态并返回结果。

## 7. 数据结构与本地 API 实现

继续使用现有 FastAPI、SQLite、原生页面结构，不因升级改为新技术栈。

### 7.1 持久化字段

| 数据对象 | 建议字段 |
|---|---|
| 代理库 | `id`、协议、主机、端口、认证信息、启用状态、校验状态、时间；输出认证脱敏 |
| 系统配置 | `proxy.enabled`、`sms.enabled`、`sub2api.enabled`、`sub2api.base_url`、`sub2api.admin_key` |
| 任务快照 | 本次成员 IDs、接码开关、代理模式与代理集合版本、集成开关与模板版本 |
| 集成模板 | 分组 IDs、账号并发、计费倍率、模型要求、默认分组行为、更新既有账号行为 |
| 推送任务 | 本地账号 ID、实例标识、凭据指纹、模板快照、状态、次数、远端账号 ID、安全错误摘要 |
| 账号/任务成员 | 增加“已成功未接码”的状态，保留支付和接码证据关联 |

代理密码、Admin Key 和真实账号产物不得纳入 Git；配置保存后不在列表回显完整值。与当前账号文件相同，运行目录和敏感文件继续排除在发布源码之外。

### 7.2 本地 API

以下接口已在源码中实现，均要求管理员认证：

| 设计接口 | 用途 |
|---|---|
| `GET /api/proxies` | 脱敏代理列表及开关状态 |
| `PUT /api/proxies` | 校验并保存代理文本；返回无效行号，不返回密码 |
| `PUT /api/proxies/enabled` | 启用/关闭代理库 |
| `GET/PUT /api/integrations/sub2api/template` | 获取/保存模板 |
| `POST /api/integrations/sub2api/test` | 只读连接和权限测试，不创建账号 |
| `GET /api/integrations/sub2api/groups` | 获取远端分组用于选择 |
| `GET /api/integrations/sub2api/pushes` | 持久化推送结果列表 |
| `POST /api/integrations/sub2api/pushes/{id}/retry` | 重试失败推送，不重新支付/接码 |
| `POST /api/integrations/sub2api/pushes/{id}/reconcile` | 只读核对结果不确定的远端账号 |
| 现有 `POST /api/batches` | 仅提交明确选择 IDs，并增加流程/代理/集成快照 |
| 现有配置接口 | 保存接码开关、sub2api URL/Admin Key/推送开关，敏感字段脱敏 |

上述接口全部要求管理员认证；参数错误应返回可读校验信息，不泄漏请求头、凭据或远端响应中的密钥。

## 8. 升级与兼容

- V1.0.0 历史任务、报告、成功库和已保存 JSON 不删除、不重写为新流程结果。
- 旧任务迁移时默认接码开启；代理与集成新开关的初始值需要明确显示，避免升级后自动外发账号。
- 集成默认关闭；在用户保存实例和启用前不能连接目标实例或推送凭据。
- 代理未配置且平台内置代理不可用时，应明确提示需要外部代理，不能伪装为可执行状态。
- 新任务保存配置快照，重启恢复或失败重试不得重复支付。
- 源码版本号和健康接口已为 `1.1.0`；Git tag 仍保持 `v1.0.0`，真实第三方联调完成前不创建 `v1.1.0` 标签。

## 9. 开发顺序与验收标准

### 9.1 建议开发顺序

1. 先复现并修复账号选择，增加精确候选列表及后端成员回归测试。
2. 实现代理库的持久化、协议校验、开关与 ytc 实际传参联调。
3. 实现接码开关、任务快照与“已成功未接码”分支，确认成功库统计口径。
4. 实现 sub2api 连接配置、真实认证契约、模板、推送队列和幂等核对。
5. 完成七模块 UI、升级迁移、安全扫描、端到端验收和发布说明。

## 10. 开发前必须确认的问题

1. ytc 是否仍接受 `proxy_source="provided"` / `proxies`，各代理协议与关闭开关的实际行为是什么？
2. sub2api 实例 URL 与版本是什么，管理员 Admin Key 使用什么请求头或认证流程？参考页仅明确 Bearer JWT。
3. 模板中的“计费”是账号倍率还是逐模型价格？“可用模型”作用于账号还是已有分组，是否允许修改远端分组？
4. 关闭接码后的“已成功未接码”账号是否进入成功库及成功总数，是否允许 AT-only 推送？
5. “取消勾选自动踢出”是否仅针对未开始任务的候选列表？若也要求移除已创建/执行中任务成员，需先确定外部订单处理规则。

以上不确定项必须在开发或联调前明确，不用猜测接口和默认值代替确认。
