# UPI Workbench · 20261012 文档实现与验收

## 1. 信息架构

V1.0 基线工作区有 **仪表盘 / 账号库 / 任务管理 / 成功库 / 设置**。V1.1.0 在此基础上增加 **代理库 / 集成**，实现版本共七项；登录页、创建向导与任务详情弹窗不作为额外模块。旧接码页、提链页、独立日志页已从 UI 移除；历史数据保留。

## 2. 页面与交互

| 页面 | 数据与操作 |
|---|---|
| 仪表盘 | 账号总数、按账号去重的全流程成功数、每 3 秒追加的虚拟终端日志；显示 ytc 真实阶段/百分比/轮次/耗时，进度不变时约每 30 秒心跳，可自动跟随滚动 |

| 任务管理 | 选择账号 → 下一步 → 确认任务名称 → 开始任务；列表名称可打开详情，显示邮箱、步骤、成功失败数、失败原因；成功 TXT 导出、失败新建重试、MD 记录下载；列表可删除非执行中任务 |

## 3. 最终执行流程

1. 导入 TXT，保留 `original_access_token`；创建任务时保存 `at_snapshot`，避免后续新 AT 覆盖提链输入。
2. 调用资格检查，要求 `token_ok=true` 且 `eligible=true`。资格失败结束该账号的后续步骤。
3. 使用 ytc 的 `ohk_...` CDK 登录，以原 AT 提链，最多尝试 **5 次**，每次失败后间隔 120 秒。已生成链接后继续等待**同一订单**的 `submission.status=completed`，不把“有链接”当作“支付成功”。
4. 支付完成的账号进入 handy 自动登录接码，尝试次数不限；失败后间隔 120 秒。暂停或服务重启后，已有订单继续查询，避免重复扣费。
5. 绑定完成后调用 handy 的导出接口，参数 `fmt=cpa` 和 `fmt=sub2`。验证 JSON、保存文件后仅从 `access_token/accessToken` 提取 AT，绝不以 ID Token 或 Refresh Token 代替 AT。
6. 写入成员 `done` 及支付/接码任务关联，进入成功库。完成或失败的任务自动写一份 MD 记录。

### 重试语义

失败重试新建任务，原记录不改。默认名称为 `任务YYYYMMDD-重试`，同日依次增加 `-2`、`-3`，不会重复拼日期。尚未支付的账号重新检查资格；已支付但接码未完成的账号从接码继续，不重复支付。

### 暂停与不确定状态

不限尝试次数不代表无间隔调用。人工暂停时停止后续尝试，保留外部订单。支付结果不确定或等待过长时任务可转为暂停，继续会查询原订单；不会以网络超时宣称支付失败再盲目扣费。暂停不是执行结束，不生成“完成”报告。

### 提链进度、状态同步与并发

- ytc `/api/tasks?job_id=...` 返回 `task.stage/progress/current_round/max_rounds/elapsed_seconds`。提链期间轮询并转换为中文终端日志；支付期间从 `results.items[].submission.status` 显示等待/执行/完成状态。进度接口临时不可用时输出提示，但不将原支付订单判失败或重新提交。
- 同一进度去重，变化立即输出，未变化时约每 30 秒输出等待心跳；日志不包含访问令牌、CDK、支付链接或代理信息。每次本地提链尝试与失败重试间隔都会输出说明。
- 成员阶段变化同时更新账号库：资格通过 → `qualified`；当前正在执行或待接码 → `processing`；任一步骤失败 → `failed` 并记录错误；全流程成功 → `done`。一个账号失败即刻更新，不等待其它账号全部结束。
- 启动升级时根据最新已执行成员阶段修正历史状态；新建但未启动任务不会覆盖之前真实失败结果。
- `app.concurrency` 默认 3，前后端都校验为非零正整数。`0`、负数、小数、科学记数法和空值不可保存。控制每个任务各阶段并行账号数（不是所有任务合并的全局限额），任务开始/继续时读取。ytc 自身并发/额度限制仍需遵守。
- 每页数量保存在浏览器 `upi_cred_page_size`，切换回第一页，持续刷新不会清除勾选账号；失效的旧分页响应不会覆盖新页数据。

## 4. 数据结构与存储

- `credentials.original_access_token`：导入 AT；`access_token`：后续接码取得的新 AT。
- `task_batches`：任务状态、累计进度、来源任务、流程版本、报告路径、软删除标记。
- `batch_members`：原 AT 快照、阶段、错误、关联提链/接码任务。
- `upi_tasks.external_job_id`：外部订单编号，暂停后继续同单。
- `account_exports`：账号、接码任务、格式与已保存产物路径；不在成功列表中返回磁盘路径或密钥。
- `runtime_logs`：程序当前执行日志；`audit_logs`：写操作与导出审计。

文件路径：

```text
data/account_exports/<账号ID>/<接码任务ID>/cpa-1.json
data/account_exports/<账号ID>/<接码任务ID>/sub2-1.json
doc/task_reports/task-<任务ID>-YYYYMMDD.md
```

外部 ZIP 文件名不直接用于本地路径；验证大小与 JSON 内容，不允许路径穿越。JSON/MD 文件权限为 `600`，账号产物目录权限为 `700`，不通过静态资源目录公开。

旧数据原 AT 若在此升级前被覆盖，无法凭空恢复，迁移时保留当前值并标识旧流程；重新导入原 TXT 可得到准确原 AT。旧成功账号若没有历史 JSON 产物，下载会明确提示文件缺失，不返回空包或伪造 JSON。

## 5. API 与格式

| 接口 | 用途 |
|---|---|
| `GET /api/configs/workspace` | 返回两个脱敏 CDK 和非敏感并发数（密码通过独立接口修改） |
| `PUT /api/configs/app.concurrency` | 请求 `{"value":"5"}` 保存并发；非正整数返回 400，不修改原值；批量配置接口同样校验 |
| `POST /api/auth/password` | 校验旧密码并修改；不把密码明文保存 |
| `POST /api/batches` + `POST /{id}/start` | 先创建再后台执行；启动失败可再次启动已创建任务，不重复建任务 |
| `GET /api/batches/{id}` | 邮箱、成员结果与报告可用状态 |
| `POST /api/batches/{id}/retry-failed` | 新建失败重试任务 |
| `GET /api/batches/{id}/export-success` | 仅导出该任务成功账号 TXT |
| `GET /api/batches/{id}/report` | 下载完成任务 MD；文件缺失时可重建 |
| `DELETE /api/batches/{id}` | 隐藏任务；保留成功证据与报告 |
| `POST /api/credentials/batch-delete` | 确认删除选中账号；任务正在使用时返回 409 |
| `GET /api/successes/export?ids=1,2` | 导出选中账号三段 TXT |
| `GET /api/successes/download?ids=1,2&format=cpa\|sub2\|both` | 按格式打包 ZIP；参数无效返回 400/422，缺少文件返回 409 |

TXT 为 `账号----密码----2fa`，每行一个，不含 AT。JSON 保留平台导出结构，不自行猜造字段。MD 只记录任务编号、邮箱、阶段、结果摘要与计数，不复制敏感原始响应。

## 6. 验收与待确认

自动化覆盖：五模块导航、设置四项、六个外链的位置与安全属性、创建向导与错误重试、资格阻断、原 AT 快照、提链第 5 次成功、接码第 7 次成功、暂停同单续跑、文件下载失败不重新接码、成功口径、历史任务保留、JSON ZIP 格式与目录权限。

浏览器验收使用独立 SQLite 与第三方替身，真实 UI/API 完成导入、选择、开始任务、详情、TXT/MD/JSON ZIP 下载、删除交互；检查 320/768/1024/1440 宽度。此验收不代表第三方线上支付与接码一定成功。

待确认/运营限制：
- 购买和 CDK 操作地址已按用户提供的网址配置；页面可验证链接绑定，但不保证外部商家库存或平台服务可用性。
- ytc/handy 可出现账号校验失败、额度不足、网络中断；代码不能替代平台保障。只有确认支付成功的账号才进入接码。
- 当前 8888 用于预览，真实敏感数据使用前应配置 HTTPS、强管理员密码与正式 JWT 密钥；本轮不改默认密码、不额外开放端口。
