# V1.3.0 提链与支付组合

供应商显示名：**春晴提链**；内部兼容 ID 仍为 `wangyou`，已有任务和历史配置无需迁移。

## GitHub 本地提链

`local` 对应项目内置的 `app/upi_zero_link` 协议实现，来源参考 `wangshen233/upi-zero-link`。它通过 `curl_cffi` 与 Stripe/ChatGPT 协议通信，不要求第三方提链 API Key；任务仍要求有效 AT 和系统代理。支持 HTTP、HTTPS、SOCKS5、SOCKS5H。

本地提链现在可以组合：

- Masi 支付（支付 CDK）
- UPI 雇主中心 `xxsyun_upi`（复用 ytc `ohk_` API Key）

## UPI 雇主中心支付

供应商 ID：`xxsyun_upi`。公开文档入口：`https://upi.xxsyun.xyz/employer/api/`。

- 基础地址：`https://upi.xxsyun.xyz`
- 认证：`Authorization: Bearer ohk_...`
- 创建：`POST /api/v1/orders/batch`
- 查询：`GET /api/v1/orders/{id}`
- 请求：`{"items":[{"at":"...","link":"https://..."}],"dispatch_mode":"auto"}`
- 使用稳定的 `Idempotency-Key`，避免请求超时后重复创建订单。
- 订单 ID 保存到 `upi_tasks.payment_order_id`，暂停或恢复时优先查询原订单。

这里的 `ohk_` 是 ytc/OrderHub API Key，可以作为支付供应商认证凭证，但不是支付 CDK。供应商向导在“本地提链 + UPI 雇主中心”组合中只要求输入一份 ytc API Key；真实密钥不会写入源码、测试或日志。

## 当前本地提链适配边界

- GitHub 协议由本地代码执行；不调用 GitHub 远程 API。
- 本地提链的账户 AT、代理和 Stripe 响应只在运行环境处理；任务报告不写入原始敏感响应。
- 本地提链需要系统代理库；创建任务时代理会保存快照，代理库为空或未启用会在启动前拒绝。
- `xxsyun_upi` 不提供供应商内置代理；支付请求会把 AT 和本地提炼返回的支付链接发送给该支付平台。
- 本次没有使用真实 API Key 创建支付订单；真实支付链路仍需专用测试授权。

## 711proxy 动态 URL

711proxy 控制台生成的动态接口可能使用类似 `http://as.rotgbapi.trustsource.live:8089/gen?...` 的 API URL，而不是 `711proxy.com` 域名。工作台已允许该官方接口域名和 8089 端口；请保留 URL 中控制台生成的区域、协议、数量和会话参数，不要手动替换鉴权参数。
